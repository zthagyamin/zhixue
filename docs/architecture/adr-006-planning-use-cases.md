# ADR-006：计划用例与页面生命周期分离

状态：M3 候选实现，验证与集成以对应 PR 的实际结果为准。正式计划和事件协议、算法参数及持久数据格式保持兼容。

今日与长线计划分别拥有读取、编辑、保存和执行状态。React hook 负责生命周期；应用会话负责接受请求、作用域核对、修订单调性、串行写入/重试与发布。Dashboard 只组合明确的来源、存储、导航和展示端口，不再持有自动协调和批准过程的多个私有 ref。

任务与长期目标规则属于 domain/planning。已有事件校验和纯进度契约在依赖需要时迁入 domain/evidence；旧导入入口保持可用，禁止同时存在两份权威实现。FSRS 库的预测适配通过端口提供，纯领域代码不依赖平台或第三方包。迁移不改变现有哈希、完成语义或跨端协议。

长期保存与刷新分开编号，较旧修订不能覆盖已接受保存。自动准备绑定账号/本机、资料库、日期、目标修订和来源版本；旧范围的忙碌操作不能吞掉新范围的请求。已开始的当前任务保留旧内容版本，不借自动刷新换题或扩张每日负担。

保存方法返回它自己的持久回执，界面可以同时保留更高的已观察修订。排队但尚未开始的写入可撤销；已经被存储接受的写入不能伪报失败或回滚。丢失回执后重试同一操作身份。旧版候选按空间和来源范围隔离，权威修订额外绑定连接；同一题库的离线候选在重连时仍可由用户明确批准。

React 适配器在生命周期中创建会话，渲染不读取会话 ref 来决定副作用。自动协调把“来源事实变化”与自身读取造成的临时忙碌区分开，但外部编辑/范围撤销必须一直传到草稿持久化之前。导航清理只归属于自己的请求，不能影响后发请求。

被新读取替代的后台请求使用明确的取消类型；宿主结束旧订阅，不把它显示成操作失败。当前请求的真实读取错误仍须向用户呈现，不能因为抑制取消提示而吞掉连接或数据错误。浏览器同时断言正常自动准备不会泄漏内部取消码。

自动协调只准备草稿。用户确认、计划批准、本机任务固定与打开题组是独立步骤，每次异步等待后重新确认来源和导航资格。拒绝、取消以及已有安排都保留，继续下一组依然使用实际完成和本页遍历的各自语义。

旧 app 文件允许作为迁移中的依赖装配入口，具体 I/O 与旧格式转换仍留在既有适配器。应用模块只接窄端口与纯契约，不接整个控制器，也不直接调用旧 app、数据库或网络。M4/M5 的后端、连接和同步拆分不在本决策中冒充完成。

本次无数据库迁移。回滚必须一起撤回新用例、宿主装配与对应兼容入口，不删除已经保存的计划和学习记录。真实模型、语义审定和延迟学习效果另行验证。
