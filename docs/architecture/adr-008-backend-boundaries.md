# ADR-008：HTTP、应用用例与后端适配器

状态：M5 独立候选实现；验证和集成状态以对应 PR 的实际结果为准。接口与执行约束见 [M5 后端接口](m5-backend.md)。

M4 已将页面来源/同步生命周期独立，但账号 API 仍在同一函数里做 HTTP、作用域选择、记录批次、计划处理、AI 预算和流输出。Companion 已拆路由文件，却仍通过广泛服务绑定回调大部分 server 业务。仅继续搬文件不能消除这些依赖。

采用领域契约、应用用例和显式端口：领域层保留纯数据/解析规则，应用层掌握一个用户意图的顺序与幂等生命周期，基础设施层实现 D1、SQLite/文件、模型 HTTP 与响应流。HTTP 外壳按原顺序授权和有限解码，再调用用例；用例拒绝越过经过核验的用户/库范围。数据库仍在最终持久边界核验约束，不能因为 HTTP 已检查就削弱数据库保护。

端口按实际业务能力定义，不传整个 request/server/globals，也不在 application 中使用 SQL、供应商密钥或页面回调。D1 现有实现保留为兼容基础设施，显式实现新接口；目录位置迁移仅在减少实际耦合时进行。Python 按功能建立窄端口，配置路径、时钟、随机源、锁和 I/O 在组合根绑定，不能因移动文件改变根目录或启动副作用。

流式 AI 分开三件事：先验证当前内容/设置并取得预算预留，再通过供应商端口执行，最后依据真实完成/失败结算。HTTP 输出编码不拥有预算政策。取消作用域覆盖服务准备、运行和读取者关闭；取消或失败不能产生完成结果。已经持久化的事实不因客户端丢失响应被回滚或再造。

保留 HTTP JSON 与 SSE 各自的现有响应头、字段、状态码和错误映射。保留记录批次逐条 blocked/accepted 回执、先决快照、幂等键、机器/浏览器角色与库绑定。迁移不修改内容/事件协议、调度参数、数据库表或学习成绩。已有取消时机缺口作为单独回归明确修复，不借架构重构静默改产品政策。

验收必须包括原接口/隔离/幂等回归、真实生产构建、完整 Python、既有浏览器矩阵、安装闭包和独立审查。静态边界只证明依赖方向；合成模型不证明真实模型表现。代码、网站、Companion 发布与用户安装保持各自授权。
