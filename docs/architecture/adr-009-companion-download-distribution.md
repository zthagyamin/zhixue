# ADR-009：安装包与应用发布包分离

状态：实施中。适用范围只包括公开的 Companion 安装文件，不改变学习数据、身份或本机安装。

## 原因与决定

完整网站归档约37.8 MB，两个安装文件约26.9 MB。当前发布工具多次上传完整包及组合安装包超时；独立的约13.5 MB EXE、ZIP归档均已成功保存并部署，实际浏览器下载与原文件SHA-256一致。这是当前环境的观察，不宣称固定的服务大小上限。

应用仍为一个模块化单体。新增的两个站点只托管静态安装文件，不处理身份、学习记录或业务请求。EXE、ZIP各自拥有固定下载来源；每个发布版本使用不可变的版本目录。

## 兼容与实现边界

- 保留主站原来的两个 /downloads 文件路径，用 GET/HEAD 307 跳转到已经发布的固定版本文件。请求参数不参与目标URL。
- src/infrastructure/downloads/index.mjs 的 companionDownloads 是版本、文件名、目标URL、尺寸和哈希的单一发布清单；构建脚本和HTTP路由共用公开入口，不在页面组件内分散维护地址。
- Worker入口在框架的静态文件索引之前调用下载适配器。生产构建实测证明后置app路由会被旧索引覆盖而返回404，不能只测试导出函数。页面、离线教程及原public源文件保持兼容。
- 构建先核对网站/Companion/分发清单版本一致，校验源文件和构建副本的尺寸、SHA-256，全部通过后才删除dist中的这两个副本。保留其他资源，失败时不得部分裁剪。
- 不能靠手动删除dist文件制作不可复现的“小包”。不扩展架构预算，不新增运行时密钥或包管理依赖。

## 后续更新规则

1. 先打包并验证新Companion源文件，再将对应EXE和ZIP发布到各自下载站的新版本目录，保留旧目录。
2. 核对两个生产下载的文件身份，再更新分发清单。文件变了而清单没变时，主站构建必须失败。
3. 运行下载路由/构建回归和完整npm test；正常推送开发分支并发布主站，记录实际GitHub和Sites源码身份。原有CI受阻时只采用用户当次明确授权的本机替代，不能声称云端通过。
4. 安装文件发布、主站发布和用户本机安装是三件事。不得自动升级用户电脑。

## 回滚

主站回退到之前已验证版本即可恢复原有下载行为；独立下载站保留已发布版本。回退分离代码时同时移除构建裁剪步骤并重新打包，保证本地安装文件随应用归档恢复。不得清空学习记录或覆盖旧版本安装文件。
