# ADR-017: Non-word attempts as durable sidecar evidence

Status: candidate implementation; integration and release require the task's separate checks.

The same recovery reader includes unfinished first drafts across days, labeled as unsubmitted continuation rather than pending assessment. A first parent's saved guided view reopens the original child instance. Reconciliation reads the latest durable submission before calling the legacy writer and verifies its complete original binding and immutable startedAt. This optional aggregate field is generated only by the first accepted checkpoint of this unreleased candidate protocol, never accepted as a mutation field or moved by autosave. Earlier rows lacking it remain unknown without backfilling a time; draft reconciliation then conservatively blocks other official outcomes. This prevents a later save from erasing the temporal boundary and does not migrate historical grades.

The group cursor is an auxiliary sidecar anchor with a closed V1 projection of source order, run identity and disjoint correct/wrong/pending/skipped sets. It holds no learner answer or grade and cannot claim a formal result. Explicit continuation saves the individual answer and traversal before advancing the cursor. Run identity is checked in the continuation read and in the serialized cursor write; CAS guards another device's update. Only an explicit confirmed restart creates a new run. Word eligibility comes from the original source contract, not a selected presentation. Snapshot changes form a different source set; old pending answers remain available under their original identity.

The pending queue reads across days and source heads without acknowledging outbox writes or starting a model call. Opening a recovered first attempt pins its existing binding and answer revision. Account recovery validates the original snapshot and retrieves its complete authenticated item pages; cacheLocalStudySnapshot backfills this dependency without changing the active head. The original event writer still verifies membership and association. Existing formal evidence can be linked without another write; a later official outcome blocks old reconciliation instead of replacing scheduling state. Missing original headers or native association stay explicitly limited and preserve raw answers.

Auxiliary guided and remediation attempts are rejected by the domain formal-claim transition even when no parent has yet been submitted. Pending evaluation can retain its diagnostic feedback, but its semantic status is still unknown. Normal input, post-submission hints and clock/view checkpoints never change frozen first evidence. Effective time excludes paused or hidden intervals and is a soft 10–15 minute target; no material-derived or real-user calibration is claimed.

First submission may additionally freeze normalized maxPreHintLevel (0 through 3) and answerRevealed. Missing fields preserve legacy unknown evidence; level zero never proves independence. Positive hint levels, explicit answer exposure and guided intent are observed assistance. Recall formal claims reapply the existing recall-hints-v1 cap from frozen evidence after device restoration: level two limits the grade to hard, reference-level three or answer exposure limits it to again. Other modes do not inherit this recall-specific policy. These additive sidecar fields do not alter StudyEventV3 or the original recall policy.

The sidecar round is a UI session identity. The existing account serializer independently generates envelope attempt and protocol round UUIDs; these are not equated to the event ID or UI round. Cloud linkage verifies the existing record event identity and full source/core/time/rating, then captures its authoritative attempt and round association. This association comes from the original writer's immutable record.

Stage 1B adds V1 attempts without changing StudyEventV3, FSRS, historical grades, or the existing immutable event writer. Domain transitions own immutable first submission, draft revision, evaluation semantics, and formal identity. Application ports keep UI intent separate from authenticated HTTP and D1/IndexedDB storage. Raw answers are explicitly authorized within an owner and library; arbitrary original-note paths, credentials and unknown fields are rejected.

Every attempt binds owner, library, published snapshot, item key, exact content hash, group and round. Draft writes use revision CAS plus an operation fingerprint. The D1 aggregate and its idempotency ledger are written in one conditional statement and read back. Unique formal event and logical group/round/item/content keys prevent distinct devices from assigning multiple official outcomes to one logical attempt. Old source snapshots remain readable after a new head; reference retrieval uses the original published membership. A child attempt retains hint, retry or remediation work and cannot create an additional formal grade.

Submission captures the first answer and its answer revision once. The absence of observed UI assistance is not proof of independence; callers must use unknown unless they have evidence. Evaluation records source (deterministic, model, self assessment) and semantic outcome (correct, partial, incorrect) separately from a scheduling rating. Offline, invalid or missing-reference evaluation stays pending and can retry the same submitted snapshot. Resolved evaluation is immutable and fingerprinted against its original reference. Formal claims freeze event ID, review time, evaluation fingerprint and final capped rating; a claim never raises an evaluation's rating. Explicit continuation still enters StudyAttemptSession and the existing event writer. Linkage requires the actual authoritative event's core hash and source/round/item/time/rating readback; the sidecar does not update projections or FSRS.

Local storage is a separate additive IndexedDB V1 database. Attempt mutation and outbox insertion commit in one transaction. Local durability permits continuation with an honest device-only status; storage failure does not. Sync preserves queued operations after transport or receipt loss, checks receipt identity and fingerprint before removal, and exposes cloud conflict. Refresh hydrates cloud attempts only when it will not overwrite unsynced local work. Local references are immutable cached published item versions, separate from answer drafts. Older servers/missing tables return an explicit unsupported capability; local records remain recoverable.

Migration 0021 adds only the sidecar table and indexes, registered in the migration journal. Retention is persistent until an authorized scoped lifecycle operation exists; this implementation has no arbitrary delete, expiry, automatic cleanup, or historical migration. Existing account/library deletion cascades apply to the new account data, without introducing a deletion endpoint. Roll back code as a group and leave the additive table intact. No real learner records, models, deployment or learning outcomes are used as verification.
