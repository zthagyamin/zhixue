# 架构迁移路线与退出条件

原则：按用户行为迁移一条完整路径，再替换旧调用；不并行启用两个成绩写入口。每个工作包保持可独立审查、验证和回滚。所有阶段沿用已有内容/事件协议，协议升级需另立 ADR。

| 阶段 | 工作 | 状态 / 退出条件 |
| --- | --- | --- |
| M0：控制继续恶化 | 根规范、PR 模板、真实依赖图、热点预算、单一安装清单 | 本次已实现；架构检查与实际安装回归进入常规验证 |
| M1：可信评价核心 | content / assessment / math 纯域，旧入口转导出，前后端对齐修复 | 本次已实现；新核心不依赖 React/存储/网络，原行为及新缺陷回归通过 |
| M2：作答用例 | 从 subject-view 和 practice-session 抽取开始、提交、持久回执、续练、取消 | 独立候选分支已实现；两宿主共用公开应用 API，保留旧宿主回归，真实双宿主浏览器进入 CI；集成以对应 PR 的实际验证结果为准 |
| M3：今日与长线计划 | 将计划准备、批准、分组选择、跨日刷新从 Dashboard 拆出 | 独立候选分支已实现；公开用例和真实 hook 回归覆盖修订单调、范围撤销、分组续练与明确批准；新增 28 个浏览器场景，实际验证与集成状态以对应 PR 为准 |
| M4：来源与同步 | 账号/本机连接和 outbox/回执服务，sources-view 只展示状态 | 独立候选实现；连接、来源应用、传输、恢复和退出有公开用例，来源页只接六组窄模型；新增 40 个浏览器场景进入 CI，实际验证与集成状态以对应 PR 为准 |
| M5：后端边界 | HTTP 只做授权/解析/响应；D1/AI 作为基础设施端口；Companion 对应应用层 | 独立候选实现；账号用例、服务端同步与提供商端口已拆分，Companion 新分层受 AST/清单约束；新增 32 个后端浏览器场景，实际验证与集成状态以对应 PR 为准 |
| M6：插件扩展 | EDU-B 补救/编程重写，EDU-C 受约束变式/数学步骤 | B/C 分支分别实现，证据见对应 PR；C 是四个规则模板与有界步骤原型，非通用证明批改 |

## M2 已落地的接口

`src/application/study-attempt` 导出 `createStudyAttemptSession` 与 `createStudyEvaluation`。前者按 scope/content/mode 绑定页面草稿，通过宿主的 current 检查账号、库与来源资格；`submit` 接受请求、`request.capture` 固定命令、`control.durable` 接受持久回执、`invalidate` 撤销显示资格。继续由同一已保存回执消费一次。评价用例管理请求锁和取消，模型调用与参考一致性仍由受控宿主和领域规则负责。

实际依赖端口为草稿 begin/commit/fail、时钟、身份生成器和执行回调。回调调用既有持久日志及独立发送链，没有另建第二份 outbox 或用空接口包装整个 Dashboard。会话区分 idle/saving/failed/saved/continued/stale；评价锁独立，临时补救没有正式写入口。

两宿主通过兼容的 `LearningDraftStore.submit` 接同一会话，插件仍只拿窄草稿接口。`PracticeSession` 向持久适配器传内部请求与回执；旧一参数回调继续兼容，Dashboard 正式适配器要求该身份。三阶段顺序和页面投影仍留在视图，M2 不宣称 M3/M4 的计划、同步职责已拆完。

EDU-B 的 `src/application/temporary-practice`（临时草稿、异步运行及原反馈回执观察）继续独立，插件通过窄端口装配 `src/features/remediation`。候选源格式见 ADR-003，正式作答兼容见 ADR-005；未改正式事件与 FSRS 协议。

## M3 已落地的接口

`src/domain/planning` 持有日计划、长线目标、任务编辑/分组/回合规则及其契约；`domain/evidence` 持有原样兼容的事件与进度契约。旧 app 导入路径作为兼容转导出，只有依赖既有存储或展示类型的代码保留为装配器。FSRS 预测通过 `infrastructure/planning` 提供，不改变调度参数。

`src/application/planning` 分别拥有本机任务会话、账号每日读取/准备、长线读写、自动协调、确认开始、题组导航和旧版计划操作。每个用例仅接所需的读写、来源校验和发布端口，不接整个 Dashboard。`features/planning` 管理 React 绑定、定时刷新和作用域撤销；`app/study-dashboard/*-planning-adapter.ts` 与 `planning-source-adapter.ts` 提供遗留 I/O/题面映射。

新增计划功能必须使用这些公开用例。晚到的读取不能覆盖较新保存；已接受持久回执与页面显示资格分开；候选绑定学习空间与来源库，旧版权威修订还绑定服务连接。任何等待之后都重新核对资格，排队中的开始也需在真正写入前核对。自动准备只能保存草稿，没有批准端口。

题组选择保持原计划与资料版本；本页已浏览项只用于续练导航，不能转换为正式完成记录。导航入口共享请求代次，切日期、模式或资料库撤销旧请求；旧请求结束不能清除新请求的忙碌状态。协议/序列化、完成语义或 FSRS 调参需要另立设计，不能混进迁移。

## M4 的责任分配

将大控制器收敛为装配根，明确提供 `studySession`、`dailyPlan`、`libraryConnection`、`syncStatus`、`appearance` 等窄视图模型。不要把旧控制器整个返回对象再命名成一个“服务”传下去。

账户切换和内容版本更新由单一作用域令牌驱动；每个异步用例在保存/应用结果前核对该令牌。跨端进度只能来自完整验证的历史投影，不通过本地缓存数量猜测已同步。

已迁移的公开 API、输入保护、同步回执和兼容限制见 [M4 来源与同步边界](m4-source-sync.md)。原有 IndexedDB 与账号 API 客户端继续作为迁移期适配器；M4 没有重写服务端授权、D1 或 Companion HTTP 分发，后者归 M5。

## 暂不做的结构变化

- 不为“新架构”更换 React、Vinext、D1 或 FSRS 库。
- 不一次搬动所有 API、数据库表和 Python 文件，不做大范围重命名后宣告耦合消失。
- 不引入通用插件 marketplace、全局事件总线、微服务或消息中间件。
- 不自动改用户安装、运行真实资料评测、补写历史成绩或调用收费 AI。

## 发布与兼容

本次阶段 A 源码从已有 PR 继承，修复后在独立分支交付；不改原 PR 分支，不关闭它、不改 main。网站上线、Companion 新包发布、用户安装是后续分别授权的操作。

新网站对旧 Companion 返回值仍进行前端一致性检查；旧客户端无法从本次 Python 源码变化自动获得后端功能。只有测试过并发布的新包才可声称包含新后端规则。新增共享文件清单仅影响未来构建，不改变现有已发布 EXE/ZIP。

## 回滚与停止条件

本次没有持久数据迁移，兼容入口仍存在；可按依赖逆序 revert 功能修复/迁移/治理提交。程序文件清单与读取器必须一同回滚，不能只删清单。任何新任务若需要改变评级、正式事件结构、历史重放或沙箱权限，应停止相关实现，提供独立设计与明确批准范围。

## 验收证据的边界

M5 责任、兼容和后续更新规则见 [后端接口](m5-backend.md)。server.py 从阶段基线 2665 行下降到约 1223 行；仍保留启动/配置/授权及旧装配，不以行数下降宣称全部历史实现已清理。旧 D1 实现保留是明确的兼容选择，不允许新应用依赖旧 db/app。

确定性回归和合成浏览器只能证明被测试路径。人工审定的语义开发/保留集、真实模型准确率与延迟学习效果仍未完成。试题应按题目家族和来源分组切分；调参看过保留集后不能继续称其未见。
