# 非单词阶段 3：执行、步骤与变式契约

状态：核心能力及1.41.1显示收尾已交付Sites132。正式事件、FSRS、历史记录和词汇学习规则沿用原有权威层；实际交付以版本回执为准，本文件不表示已通过真实材料验收。

## 所有权与来源

插件表达输入、运行、提示、重试与继续意图。共享宿主负责生命周期，应用服务负责核对，存储与模型适配器负责其各自端口。插件没有直接模型、正式成绩、调度或跨账号存储端口。

账号来源必须是该用户、资料库中完整发布的原始快照成员。恢复读取原快照，不替换为当前头版本。Native 来源通过已配对 Companion 捕获；`NativeMathCapture` 保留原 `contentHash` 与 `localBindingHash`，它们不是便携条目哈希。捕获、来源关联、核对请求均按用户、资料库与材料版本隔离，原 Obsidian 文件只读。

## 执行报告与内容

- `CodeRunReportV1` 绑定运行、作答身份、非负答案修订、来源与测试版本。可信执行层提供阶段、异常对象来源和原代码位置；客户端与沙箱严格校验封闭字段。
- 新 `CodeLearningSupportV1` 提供函数名、JSON 参数、预期值及可选预设提示。函数案例只调用一次，实际值来自该次调用。合法结构化用例可替代旧断言脚本；旧格式仍须有有效测试材料，无效新配置不借旧脚本绕过检查。
- 自动导入的前缀行数独立保存。显示位置对应原代码，测试缺陷、环境、取消、超时和无法归因均不形成用户失败证据。
- 公开检查通过只说明这些检查项通过。完整输出与 traceback 单独保存，不塞进执行报告。

## 独立练习证据

`PracticeEvidenceV1` 是新增侧车，绑定已有 `LearningAttempt`，不扩充严格 V1 checkpoint 字段。执行首报告与首输出不可覆盖；最新报告、提示、步骤、变式及补练导航独立记录。运行 ID 可以在页面刷新后重置，不能作为持久排序依据；报告或输出变化时旧提示不再作为当前提示。

侧车总量限制为 128 KiB UTF-8、256 条操作回执，无回执淘汰。步骤文本最多 8000 UTF-16 单元，提示 2000，解释 4000，每份执行输出 20000。既有答案与 checkpoint 限额不放宽。超限或写入失败保留此前可靠记录并显示错误。

本机写入等待 IndexedDB 事务完成；账号同步复用同一操作身份和指纹。原始作答先同步，依赖的证据随后同步。合法较早回执只确认对应前缀，不回滚较新的本机内容；首次报告引入回执由本机私有元数据证明。

两个必要提交屏障：

1. 步骤输入（包括清空）先取得保存回执，账号模式下在答案冻结前确认其同步，避免提交状态超越步骤写入。
2. 编程运行报告先可靠保存并同步，再允许首轮正式结果占位，避免正式结果超越其运行证据。

编程执行准备还有输入屏障：当前编辑器代码先通过原宿主 checkpoint 保存，再创建或复用执行子作答。不可变首轮答案不改；恢复读取已保存的编辑器草稿，不根据文本是否等于首轮答案猜测它是不是过期。用户主动改回原代码仍是有效新草稿。保存失败或等待期间切题都阻止后续运行准备。

无法取得回执时保留输入与证据，提供明确的待保存／待核对状态；不得用未知替代正确、错误或自评。

## 计算与步骤

`CalculationSupportV2` 增加必要条件、单位、可选步骤和映射 ID。V1 保持严格解析。无配置的旧数值题仅在权威参考可被现有数值内核可靠解析时使用兼容核对；不猜变量、定义域或符号规则。

最终结果与步骤诊断独立。正式成绩只按最终结果；可靠最终结果不因步骤未知或步骤反馈保存失败而变成错误。无法核对的最终结果不产生正式成绩。步骤文本随提交冻结；正式结果之后可将同一冻结步骤从待核对补为可靠诊断，不改最终成绩。

默认最终结果评价不调用语义模型。用户明确点击“核对这一步”才调用语义服务。模型结果须结合原任务、来源参考和实际作答证据，绑定答案／步骤修订；不按长度、关键词或置信度判定。预算、配置与已完成请求缓存沿用现有服务，回执丢失复用请求；收到可靠的待核对回执后，后续明确重试可新建服务尝试。

## 经审核的映射与临时变式

原题仅保存 `variantMappingId`。独立 `MathMappingPreparationV1` 绑定原快照、条目、内容哈希、模板版本、参数及来源条件，并包含真实内容准备时的原文引用与审核理由。引用上限 1000、理由上限 2000；条件按规范化集合匹配，重复条件拒绝。

账号发布只允许既有可信来源发布设备；Native 发布复用配对与 Origin 边界。学习插件只读映射，没有选择模板、勾选相关性或发布“批准”标记的流程。技术校验并不证明任意审核理由正确；真实材料仍需最终教学验收。

首批仅使用 `cancel-domain`、`sqrt-sign`、`context-linear`、`inverse-linear`。参考由有限规则重建，不信任客户端答案、定义或预期结果。种子、参数、模板和变式哈希可复现；参数本身须经审核。

公式呈现由 `src/features/calculation-study/variant-math.ts` 提供显示投影，仅对已知版本、有效参数且与模板重建完全一致的题干、条件及参考加入数学排版。原变式对象、种子、参数、哈希、答案及判题参考不变；定制原文、未知版本、代码和已有数学标记保持原样。页面使用现有 `MathText`，完整变式解法按需展开，显示投影不得回写存储或传入判题服务。

变式只能附在真实补练子作答，父作答必须已提交且用户、资料库、快照、条目、来源、分组、轮次完全匹配。D1 提交同时固定父作答原 JSON 与修订。变式不能替换首轮题目或成绩。描述先保存，再开放输入；V1 `instanceId` 保存创建意图，刷新恢复同一道题。缺映射时原题重试，不展示虚构变式。

## 恢复与兼容

“待核对答案”与“待核对步骤”是不同队列。最终成绩已保存后，非空的未核对步骤仍可从独立入口恢复。列表读取不调用模型；核对步骤没有正式事件或调度写入端口。Native 可能幂等确认已知正式事件的安全屏障，它不创建或修改成绩。

分页不完整明确显示，不能包装成完整恢复。损坏诊断只允许生成只读、不可核对的安全原文投影；严格读取、模型写入和存储记录不因此放宽。来源缺失、身份不符或两设备冲突保留原内容并停止争议操作。

新增能力通过 `native-math-v1`、`native-math-variants-v1` 和账号受控动作提供。旧服务缺少新能力时明确不可用，不自动降级评分。新增 SQL0023／0024 与程序清单追加，不迁移或删除旧成绩。
