# 知学 CI：以实际提交为准

唯一长期入口是 `.github/workflows/ci.yml`，名称 **知学 CI**。在当前开发分支 `refactor/ui-redesign-s1-settings` 查看提交检查，先看 **CI 总结果**，再展开失败的具体任务。工作流标题、摘要及 artifacts 均标注实际验证 SHA；旧失败通知不能当作最新提交状态。

## 触发与提交身份

向 `refactor/ui-redesign-s1-settings` 或 `main` 推送时自动检查；目标为这两个分支的 PR 也自动检查。其他工作分支不因每次 push 重复消耗 CI，请通过 PR 交付。开发分支自身的 push 与它指向 main 的 PR 检查分别验证开发提交与合并候选，不伪称两者相同。

每项检查直接 checkout `${{ github.sha }}`，并核对 `git rev-parse HEAD`。push 检查实际推送提交；`pull_request` 检查 GitHub 的临时合并提交，`source-identity.json` 另存 PR head/base SHA。CI 不再在运行中应用补丁、创建代码提交，或偷偷切换到另一条分支。

同一分支 / PR 的旧执行会被新执行取消，不影响其他分支 / PR；取消不等于通过。工作流未设置路径跳过、不自动忽略 draft PR，也没有 `continue-on-error`。已完成的历史失败不删除、不改写。旧临时分支仍保留，今后不要向它们继续推送或复用临时工作流；它们没有被本次修改禁用。

工作流预留 `workflow_dispatch`。GitHub 网页手动运行入口依赖默认分支存在该文件；本次只改开发分支，**不承诺 main 合入前有 Run workflow 按钮**。已有运行可使用 Re-run failed jobs；不同代码应产生新的提交和运行，不能把旧 SHA 的重跑称为新代码验证。

Node 汇总从本次原始日志提取；总数至少保留原有 1672 项并要求全通过，新增 CI 报告单测会使实际总数增加。缺少完整 TAP 汇总、非零退出码、任何 skipped/cancelled/todo 都判为未通过；不硬编码一个“全部通过”的展示数字。浏览器结果必须匹配当前 SHA、声明完整并包含全部通过场景。

Python 使用 `npm run test:python` 运行真实 unittest discovery。非零退出码使完整校验任务失败；`python-result.json` 单独保存执行数、通过数、错误及每个条件跳过的名称和原因。环境不支持符号链接等条件跳过不能计为通过，交付必须如实列出；不与 Node 数量混加。测试用例目前允许的条件跳过不等于整个 CI job 可以跳过。

## 日志、失败与通知

每次运行的 Summary 显示实际提交和结果；Artifacts 保留 14 天，名称包含 SHA 与重试序号。完整测试保存原始日志及其 SHA-256；浏览器保存逐场景结果、日志和对应成功截图。若环境安装在测试前失败，不会编造测试数字，直接看失败的安装步骤；若 checkout/runner 启动前失败，可能没有 artifact，但任务不能因此变绿。

npm 与 pip 使用依赖文件键控缓存，仍实际执行 `npm ci` 和既有 requirements 安装，不跳过测试。Actions 固定为明确的 commit SHA；Node/Python 沿用主/次版本选择，runner OS 与 Python requirements 并非完整环境锁，不能宣称字节级可复现。

不通过关掉个人通知、吞掉退出码、删旧运行、跳过断言来减少红叉。精简的是零散入口和过时的重复执行；真正的新失败仍会显示。

## 安全与交付边界

仅 `contents: read`，checkout 不保留写凭据，无部署 job、无生产 secrets、无生产数据库 / 笔记库访问。浏览器外站请求被阻断，夹具只启动本地服务器。未修改学习算法、数据模型、生产配置或原有测试断言。

**CI 总结果是汇总检查，不等于已经启用 GitHub 分支保护。** 本次没有更改默认分支、分支保护、仓库权限、通知设置或 main。以后配置必需状态检查时可选择名称稳定的 `CI 总结果`，但还应保护工作流文件的修改权限，不能把可随意改写的 CI 当作安全边界。

**通过也不表示零警告或完成依赖安全审计。** 2026-09-12 首次统一运行的原有依赖安装日志报告 npm audit 21 项告警（1 low、6 moderate、14 high），ESLint / 构建 / Actions 运行时也可能保留警告。本次没有升级或强制修复依赖；需另行检查依赖路径、生产可达性与升级兼容性，不能直接把告警数量等同于已确认的线上漏洞数量。

开发交付请报告：开发分支名、实际提交、该提交对应的 CI 运行、CI 总结果，以及“仅代码推送 / 已部署 / 线上验收”的区别。失败后在同一交付分支修复，让最终记录直接关联最终代码；不要为一轮修复再造一套临时工作流。

## 本地报告器与夹具自检

### 经明确授权使用本机替代托管运行

托管 Actions 因额度、计费或调度未启动时，应区分平台失败与代码失败。本次用户已明确选择免费本机验收；不修改计费、不伪造远端成功，也不放宽原有断言或绕过实际分支保护。

在记录准确分支、提交/源码差异后，使用 PowerShell 7 和项目依赖执行 `npm test`、`npm run test:python -- --report <结果路径>`，保留完整输出、退出码、跳过原因和产物哈希。Windows 需正确设置 `PYTHON`、`PYTHONUTF8=1` 和运行时路径。代码或环境未变的历史结果可以注明复用，不得包装成当次执行。

题组交互的本机隔离页可用 `node --experimental-strip-types scripts/grouped-study-local-preview.mjs <证据目录>` 启动；访问命令返回的 URL，通过支持的浏览器工具操作。它使用真实页面/账号接口、合成账号、内存数据库，并阻止连接真实 Companion 和外部模型。`/__fixture/layout` 提供真实入口组件与生产 CSS 的核对状态几何对照；点击轨迹仅保存在指定本机目录。若已有自己启动的 4198 开发服务器，可加 `--external-dev` 复用，脚本不会关闭外部服务器。

本机交互验收应覆盖实际断点与主题、单次点击、核对状态切换、续题、额外巩固和退出恢复。只报告实际执行的场景；几次手动交互不等于整套浏览器矩阵。不得为通过测试加入固定等待或重复点击。诊断轨迹与截图不能作为真实学习成绩。
